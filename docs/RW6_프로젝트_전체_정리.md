| 항목 | 내용 |
|---|---|

**절대 하지 말 것**

- MiFaceDown의 **"펌웨어 선택 / 펌웨어 설치"** — 워치가 꺼졌던 사고가 있었음. `.bin`은 "워치페이스 선택", `.rpk`는 "퀵앱 선택"만 사용.
- **워치페이스를 앱이 자동으로 바꾸는 방식** — 0.44에서 패처 워치페이스로 바뀐 뒤 돌아오지 못하고 블루투스가 끊겼음.
- 워치페이스 버튼의 앱 번호 **023, 143**(워치 꺼짐), **113**(언어 선택·재부팅). **2B3**은 사용 중이라 건드리지 않음.
- 폰트 패처에서 이름표 패치에 **'복원'** 누르기. 한글패치(RW6KorPatcher)를 다시 돌리면 폰트·앱 이름이 기본으로 돌아감.
- 워치에 메신저 알림 **원래 판과 위챗 자리 판을 같이 설치** — 위챗 자리 판 하나만.
- 참고한 Gadgetbridge·AstroBox-NG는 AGPL → **방식만 참고, 코드 복사 금지**.

## 3. 폰트 축소 패치와 앱 이름 패치

- 룽즈님의 RedmiWatch6-ResourcePatcher 방식 그대로, 받아오는 주소만 이 저장소로 바꿈. 패처 워치페이스 이름은 **"RW6 Small Font"**(687261404.bin, 저장소에는 bin 없음). 워치페이스가 저장소의 `lua/rw6-font.lua`와 `patches/…/font/3.100.043/`을 읽어 패치.
- 폰트 패치는 파일 3개·재부팅 3번(Medium → Demibold → Regular). 크기 변화는 마지막에 보임.
- Body류 = 알림 본문(Regular)만 줄임, Medium류 = 메뉴(Medium)만 줄임.

| 패치 | 내용 |
|---|---|
| NanumSmall85Body / 80Body | 본문 85% / 80% |
| NanumSmall85Medium / 80Medium | 메뉴 85% / 80% |
| NanumSmall85Both | 본문·메뉴 둘 다 85% |
| NanumSmallBody85Menu80 | 본문 85%, 메뉴 80% |
| BinggraeBody85Menu80 | 빙그레체, 본문 85%, 메뉴 80% |
| AppName-MessengerNoti2 | 워치 앱 목록의 "WeChat"을 "메신저 알림"으로 |
| AppName-WeChat | 위 이름을 되돌림 |

- 앱 목록 이름은 앱이 아니라 펌웨어 번역표(`messages.mo`의 `wechat.appname`)에서 옴 → 그 한 줄만 바꾼 조각을 만듦.
- **미확인**: 새 폰트 조합과 이름 패치가 워치에서 실제로 적용됐는지.

## 4. 메신저 알림 (RW6 알림)

폰이 카카오톡·문자·고른 앱의 알림을 읽어 워치 퀵앱으로 보냄. 워치 기본 알림보다 긴 글·사진을 볼 수 있음.

- 글 알림은 글(JSON)로 보내 워치가 직접 그림. 사진은 글 알림이 먼저 오고 사진이 도착하면 바꿔 끼움(세로 640px 한도 — **5000px로 하면 워치가 재시작됨**).
- 폰 설정: 글자 크기, 보낼 앱 선택(아이콘 표시, 고른 앱이 위로), 사진 함께 보내기, 진동, 화면 깨우기, 조용히 받는 시간, 묶기, **최대 보관 수 20~80**(4.4, 원래 40개 제한은 펌웨어가 아니라 우리 앱 상수였음).
- 앱 아이콘이 회색 빈 네모로 뜨던 문제(카카오톡): 적응형 아이콘을 직접 그려 합성하도록 고침(0.60).
- **위챗 자리 판(0.61)**: 워치페이스 버튼은 정해진 번호의 앱만 열 수 있는데 253번이 위챗. 메신저 알림의 패키지 이름만 위챗으로 바꿔 설치하면 **253번 버튼이 메신저 알림을 엶(확인)**.
- **고정 버튼(4.5, 확인)**: 읽기 화면에서 대화를 고정 → 목록 맨 위, 새 알림이 와도 유지, 고정한 대화는 최신 30개까지 따로 보호.
- 4.6에서 셔터를 넣었다가 4.7에서 뺌(카메라 셔터를 별도 앱으로). **4.5와 4.7은 버전 숫자만 다름.**
- 교훈: 앱 업데이트 뒤 폰의 알림 접근이 끊기면 테스트는 되는데 실제 알림만 안 옴 → 알림 접근을 껐다 켜기.
- 안정판 기록: 2.7(`stable/noti-2.7/`).

## 6. Mi Manager (폰 앱 하나로 워치 직접 연결)

Mi Fitness와 MiFaceDown을 대신하려고 2026-11-13에 시작. 폴더 `hub/`, 패키지 `io.github.hugdoublek.rw6hub`.

### 6-1. 연결 (1단계, 확인)
- 샤오미 계정 웹 로그인 → 인증키 → 블루투스 SPP로 직접 연결·인증 → 워치 정보.
- 보안 연결은 실패하고 insecure로 붙음.
- **끊김 원인 세 가지를 찾아 해결**: ① 네트워크 채널(7)에 ACK를 보내면 안 됨 ② 워치가 IP를 못 받으면 57초 뒤 끊음 → 앱이 10.1.10.2를 줌 ③ **Mi Fitness가 몇 분마다 워치를 가져감** → Mi Fitness의 '근처 기기' 권한을 끄면 유지됨. 이 재연결이 통화 소리 경로가 바뀌던 원인이기도 했음.

### 6-2. 퀵앱 중계 (2단계, 확인)
- 메신저 알림·메모의 폰 쪽 코드를 Mi Manager 안으로 합침. 워치 퀵앱과 메시지 주고받기, 앱 열기, 설치 목록.
- 원본 `noti/`·`memo/` 폰 코드를 고치면 `hub/` 쪽에도 옮겨야 함.

### 6-3. 설치 (3단계)
- 퀵앱·워치페이스·펌웨어 전송. **퀵앱 설치는 확인**(카메라 셔터를 이걸로 설치). 워치페이스 설치는 따로 확인한 기록 없음.
- 펌웨어는 넣긴 했지만 **한 번도 쓰지 않았음**. 여러 겹으로 막아 둠(파일 검사, 배터리 50% 이상, '설치' 직접 입력).

### 6-4. 시간·언어·날씨 (확인)
- 연결 때 언어(ko_KR)와 시간을 맞춤. 시간대 값은 지그재그 정수여야 함(일반 정수로 보내 시간이 틀렸었음).
- 날씨: Open-Meteo로 현재·일별·시간별 예보와 대기질을 워치에 보냄. 값은 지그재그 정수, 예보는 최고·최저 순서. "현재 위치로 날씨 업데이트" 버튼(누를 때만 위치 사용).

### 6-5. AI 비서 (크라운 길게 = 샤오아이 가로채기)
- 워치가 보낸 음성(Opus)을 받아 Gemini에 물어 답을 워치에 띄우고 읽어 줌.
- Mi Fitness의 블루투스 기록을 해독해 실제 순서를 알아냄: 듣는 중 글자 → 멈춤 → 최종 글자 → 답(토스트) → 읽기 지시 → 카드+끝.
- **확인**: 답이 화면에 뜸, 워치 스피커로 읽기(음성 인식용 통화 채널로 재생), **타이머 설정**("1분 45초 타이머").
- **포기**: 답한 뒤 샤오아이 화면을 자동으로 닫기(여러 방법 모두 무효).
- **불가 확정**: 워치의 무음(종 모양) 자동 감지 — 순정도 무음에서 소리를 냄. 대신 앱 스위치와 음성 명령("조용히 해" / "소리로 말해").
- **미확인**: 알람 설정.

### 6-6. 건강 (0.63~0.67, 진행 중)
목표: Mi Fitness의 건강 기능을 모두 Mi Manager로. 순서 = 걸음·칼로리·활동 → 수면 → 심박·산소·스트레스 → 운동 기록.

- **확인**: 실시간 걸음·심박·칼로리, 기록 동기화, "지금 동기화" 버튼, 자동 동기화 주기(1분~12시간).
- 워치에 "받았음"을 일부러 안 보냄 → 워치 기록이 지워지지 않아 다시 받을 수 있고 Mi Fitness도 가져갈 수 있음.
- 실제 파일로 알아낸 형식: 하루 활동 상세(분당 12바이트: 걸음·칼로리·거리·심박·산소·스트레스), 하루 요약(걸음·심박 최고/최저/안정·서 있기·칼로리). 워치는 동기화마다 '지난번 이후' 조각을 새 파일로 줌 → 분 단위로 합치고, **합계는 요약 값을 씀**.
- **미확인**: 0.67의 날짜별 요약·시간대별 걸음 그래프 화면.
- **아직 못 한 것**: 수면 단계, 직접 측정 기록, 운동 기록, 샤오미 계정의 과거 기록, 쌓이는 기록 파일 정리.

### 6-7. 폰 찾기 (0.66, 확인)
- 워치의 "장치 찾기"를 누르면 폰이 알람 소리 최대 + 진동. 워치나 폰에서 멈춤, 60초 뒤 자동 멈춤.

### 6-8. 화면
- 어두운 배경의 카드형 첫 화면: 연결 상태, 기능, AI 비서, 워치, 계정, 기록(전체 보기·복사·지우기). 문제가 생기면 **기록 복사**로 원인을 찾음.

## 7. 카메라 셔터 (워치 퀵앱 1.6 + Mi Manager)

워치의 원래 카메라 앱은 블루투스 입력 기기(HID) 방식인데 중국판 펌웨어가 응답하지 않아 못 씀. 그래서 워치에 새 앱을 만들고, 폰에서는 접근성 서비스가 삼성 카메라의 버튼을 대신 누름.

**워치 화면**
- 오른쪽 아래 **사진 / 동영상** 고르기(폰 카메라도 같이 바뀜)
- 가운데: 사진은 흰 원(촬영) / 동영상은 빨간 원(녹화 시작) → 녹화 중에는 빨간 네모(끝)
- 왼쪽 아래: 타이머 OFF→3→5→10초 / 녹화 중엔 일시정지 / 일시정지 중엔 빨간 세모(다시 촬영)

**확인된 것 (사용자 시험)**
- 사진, 타이머, 동영상 녹화·일시정지·다시 촬영·끝내기
- 폰을 세워도, 양쪽으로 눕혀도 모드 전환이 한 번에 됨
- **0.79: 폰 화면이 꺼져 있거나 잠겨 있어도 화면을 켜고 카메라를 엶** (잠금은 풀리지 않고 잠금화면 위 카메라만 뜸)

**핵심 방식**
- 지금 모드는 화면에서 읽고(`shooting_mode_list`), 고른 모드 칸이 가운데 온다는 점으로 칸 순서를 판단해 목표 칸을 바로 누름.
- 누른 뒤에는 정해진 시간이 아니라 화면이 실제로 바뀔 때까지 확인.
- 상태를 앱이 기억하지 않고 매번 화면에서 읽음.

자세한 신호·버튼 이름·시행착오는 `stable/cam-1.6/README.md`.

## 10. 크게 배운 것

1. **추측으로 만든 것은 한 번에 안 된다.** 기록에 실제 화면·신호를 남기게 하고, 그 기록으로 고치는 쪽이 빨랐음(샤오아이 순서, 카메라 버튼 이름 모두 그렇게 풀림).
2. **고정 시간으로 기다리지 말고 실제로 바뀔 때까지 확인.** 1.2초 뒤 확인은 성공도 실패로 읽었음.
3. **상태를 따로 기억하지 말고 매번 읽기.** 한 번 어긋나면 계속 틀림.
4. **Mi Fitness와 동시에 쓰면 연결이 끊김.** '근처 기기' 권한을 꺼야 함.
5. **워치를 바꾸는 동작은 최소로.** 워치페이스 자동 변경, 펌웨어 전송은 사고로 이어짐.
6. 워치가 주지 않는 정보는 만들 수 없음(무음 상태, 실시간 걸음, 샤오아이 화면 닫기).
